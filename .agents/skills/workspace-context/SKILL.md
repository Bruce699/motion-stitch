# Work with the person and the files

The complete command/context contract is in `docs/agent-interface.md`. Use `npm run cli -- capabilities` to discover schemas and `views` to choose a viewer. CLI and MCP share the same validated commands. `TILT_URL` plus a runtime-injected `TILT_TOKEN` selects a compatible remote endpoint with no local fallback; it does not deploy or enable a hosted service.

For authored-output review, prefer `npm run cli -- review '{"times":[0,2,5],"focus":["ui/payment"]}' --scene <id>` or MCP `tilt_review`. This needs no connected viewer or computer-use capability and does not move the person's playhead. It returns ordered frames, native-pixel semantic crops and sampled camera/source context; `compareTo` matches a saved review, and optional motion previews run separately. MCP attaches image blocks directly. Read `docs/agent-review.md` for selective artifact retrieval and fidelity boundaries. Use the viewer workflow below when the task specifically concerns what the person currently sees in the editor.

1. Read `docs/compositions.md` when working with nested compositions or multiple cameras. Existing scene IDs and folder names remain compatible. Read `.tilt/context.json` and the active scene folder. For a specific tab, read `.tilt/views/<viewId>.json`. Check timestamps, connected state, scene ID, requested/presented time, mode, inspection, selection and displayed/document revision. A stale observation is not the current screen.
2. Use `npm run cli -- context --fresh --view <id>` when exact current context matters. This asks that viewer to acknowledge. Captures also acknowledge the presented frame and save paired PNG/JSON files. Inspect actual pixels before claiming a visual result.
   Context always returns a snapshot with `active`; fresh reads also include `acknowledgedAt` and `acknowledgedViewId`. Distinguish scene `duration`, `timeline.start/end`, `requestedTime` and `presentedTime`. `selectedTracks` provides names, timing and bindings. `scenes` reports known revisions and pending edit ownership. `watch --view <id>` streams changes; `wait-for-change <cursor> --timeout 10000` is a bounded alternative. An unchanged heartbeat refreshes timestamps without waking observers. `wait-for-frame <revision> --view <id>` verifies presentation without moving the user's playhead.
3. Files are creative authority. Write scene JSON, TypeScript/JavaScript, source builds and assets normally. The agent is not required to use MCP or a file-writing CLI. Never write runtime observation files as a control mechanism.
4. For coordinated writes: get the revision from `state --scene <id>`, then `begin "Edit description" <revision> --scene <id>`. Save the returned ID. The old complete scene stays displayed while files are changing. Validate, then `apply <id> --scene <id>`. An unfinished group remains open across restart. Do not adopt or discard someone else's group silently.
5. Use `command` with `{type:"edit_begin",label,revision,paths:[...]}` when the exact write set is known. Apply and discard refuse changes outside that set. This detects unexpected files, not a competing writer's intent inside a shared file. Coordinate overlapping work explicitly.
   The CLI also accepts `begin "Edit description" <revision> --paths '["scene.ts"]'`. Codex uses its task ID as the default edit actor. Other agents should keep `TILT_ACTOR` stable, or pass `--actor` on each call. Apply/discard and API file writes reject another actor's group. Keep the original identity across restarts; ownership is coordination for trusted agents, not authentication. Use revision guards for single-field edits and the last-read hash for file API writes.
6. Undo/redo includes code, document and binary assets. Do not separately revert files in Git while assuming Tilt history remains unchanged; it will observe that as another file edit. History is local and not a substitute for a Git backup.
7. Source IDs and `data-tilt-id` selections are semantic context. Independent layers are explicitly declared in `sources[].layers`; follow the `ui-layers` skill for depth or isolation. Read context `layers` for the presented hierarchy, bounds and local transforms, and `layerWarnings` for paint dependencies. A whole browser surface does not automatically expose every DOM element as a layer.
8. Pan/zoom/orbit describe how the person is inspecting the canvas. Preserve the view while editing. Context `camera` is the saved scene projection, preset and orientation; read `docs/camera.md` before changing it. Perspective and Orthographic both support inspection orbit; Shift/right/middle-drag pans. Change the authored camera only when the creative request calls for it. `view source` and `view camera` switch inspection mode; `seek`, `capture`, `play` and `pause` target the active viewer unless `--view` is supplied.
9. For sharpness, read `outputSize`, `previewSize` and `sourceQuality`. These distinguish the saved video dimensions, Retina viewer backing pixels and actual source capture dimensions/density. A preview can use higher Auto density due to inspection zoom; that does not change export. See `docs/resolution.md` and inspect the effective limit before claiming sufficient close-up detail.

The local runtime can run with `npm start -- --browser`; open `https://tilt.video` in Codex or a normal browser. First-time setup is `npm run setup:url` (administrator approval for the local HTTPS proxy, certificate trust and hosts mapping; public DNS stays unchanged). The repo lives at `/Users/jaytel/Developer/tilt`. Use `npm start -- --direct --browser` only when a direct port is intentionally needed for isolated verification. `desktop` opens the optional native window. Closing either viewer does not stop the runtime or render queue. `stop` stops the runtime; detached exports continue. If no viewer is connected, read files and use scene commands, or open the URL before requesting transport/capture.
